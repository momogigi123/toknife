# Token 高級優化方法（v2.0 增補）

> 整合自外部專業報告（2026-08-12，豆包 LLM 產出），與本技能互補。數字為外部估算值，實施前以官方與實測為準。
> 原則：**先測量 → 逐項優化 → 驗證質量**；不要一次全開。

## 速查：輸入端（省大錢）

| 方法 | 降幅* | 要點 |
|------|:---:|------|
| Tokenizer 選擇 | 25–35% | 中文任務選 o200k/中文優化模型；勿在 GPT-4(cl100k) 上跑大量中文（1.85 token/字 vs o200k 1.0） |
| System prompt 用英文 | 20–40% | 指令/工具描述/函數名用英文（省 50–70%），交互與輸出用中文 |
| 數據格式 | 50% | 表格用 CSV 替代 JSON；高頻固定結構用自訂緊湊格式 |
| 工具回傳強制 Schema | 40–70% | 工具定義時就控制回傳：摘要+Top-N+異常，不返回原始資料 |
| 工具懶加載 | 25–40% | 初始只載 3–5 核心工具；20 工具 schema ≈12K token，懶載後省 8–10K/輪 |
| Delta Prompting | 40–65% | 多輪只發增量：`[摘要:前輪結論]+[新問題]`，5 輪以上省 60–80% |
| RAG rerank | 30–50% | 先檢 20 chunk → rerank → 只送 top 3；chunk 按任務調 200–1200 字 |
| Prefix Cache 精細操作 | 15–40% | 穩定內容（system+工具定義+歷史摘要）**全放最前**；勿在 system 插動態內容 |

## 速查：輸出端（省小錢）

| 方法 | 降幅* | 要點 |
|------|:---:|------|
| JSON Mode | 10–25% | 強制結構化輸出，消開場白/總結 |
| 動態 max_tokens | 15–35% | 分類=10、摘要=200、程式=1000、分析=2000，勿統一 2000 |
| 停止序列 | 10–20% | `\n\n`、```、`用戶：` 截斷多餘生成 |
| temperature=0 | 15% | 事實任務低溫；高溫輸出平均長 15–30% |

## 速查：架構端（省最多，難度高）

| 方法 | 降幅* | 要點 |
|------|:---:|------|
| 語義緩存 | 30–70% | embedding 相似度 >0.95 直接回快取；客服 FAQ 命中 60–80% |
| 精確緩存+工具結果緩存 | 30–50% | 相同 prompt 哈希命中；高頻工具結果快取 5–60 分鐘 |
| 規劃-執行分離 | 35–50% | Planner（便宜模型）出 JSON 計畫，Executor（強模型）只接當前步驟上下文 |
| 狀態機替代 ReAct | 50–60% | 確定性步驟用程式碼，LLM 只在決策節點呼叫 |
| 多 Agent 共享記憶 | 40–60% | 傳引用+結論，不傳完整上下文；交接用任務交接單 |

\* 總成本降幅（含輸入+輸出），外部估算，非本技能實測。

## 基礎設施層（降每 token 成本，不省 token）

- 推測解碼：小模型起草、大模型驗證 → 吞吐 2–3×，等效成本降 50–65%
- 量化：INT8 精度損 <1%、顯存減半；INT4/AWQ 顯存減 75%
- 連續批處理（vLLM）：GPU 利用率 40%→90%+，單 token 成本降 50%+

## 風險與權衡

| 方法 | 風險 | 緩解 |
|------|------|------|
| 語義緩存 | 答案不匹配/過時 | 閾值 0.95+、TTL 過期、回饋糾錯 |
| 過度壓縮 | 丟細節→答案錯 | 保留關鍵事實清單；定期全上下文校驗 |
| 小模型路由 | 判斷錯→質量降 | 置信度閾值，低置信自動升級強模型 |

## 實施路線（參考）

1. **立即（低難度）**：英文 system + 動態 max_tokens + JSON Mode + 工具回傳改精簡 + 工具懶載
2. **1–2 週**：語義緩存 + Delta Prompting + RAG rerank + 工具結果緩存 + 任務路由
3. **1–2 月**：規劃-執行分離 + 狀態機 + 多 Agent 共享記憶 + 自建部署優化 + 成本看板
