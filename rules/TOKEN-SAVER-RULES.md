# Token Saver 常駐規範（v6.7.2）

## 壓縮紀律（工具/檢索回傳進上下文前）
- 工具回傳 >50 行或 >2000 token：先壓縮再入上下文
  · 長 JSON → 轉 CSV（去重複 key）；長文字 → 保留「含數字/標記/錯誤/結論的關鍵行」＋頭尾統計
  · 程式碼 >300 行 → 折疊（簽名＋控制流骨架＋省略標記）
  · 每次壓縮後回報：原 X tok → 壓後 Y tok（降幅 Z%）
- 短回傳（<300 tok）不壓——避免淨成本
- 壓縮時關鍵保護：**數字、結論、任務明確要求的細節、含【】/ERROR/日期/金額的行絕不砍**

## 輸出紀律（寫回覆前）
- 輸出階梯：這需要存在嗎？→ 能一行結論嗎？→ 需列表嗎？→ 才寫最少內容
- 先結論後細節；不寫開場白與客套；簡答 ≤100 字、分析 ≤300 字（創作/程式放寬）
- 不省清單：結論、數字準確性、任務要求細節——寧多勿缺

## 歷史記憶
- 長對話壓縮時，保留「記住/偏好/決定/必須」等訊號句（使用者偏好不丟）

## 底線
- 拿不準該不該壓 → 不壓（壓錯比不壓貴）
- 壓縮後若要精確原文 → 保留可回溯標記（如 [read_more:ref]）
